# 手机端操作手册

> [🏠 返回主文档](../../README.md) · [🌐 English Guide](../../README.en.md) · [📡 远程访问指南](../remote-access.md)
>
> 在手机/平板上连接天枢桌面端：扫码或令牌接入，远程查看会话、处理审批、发起新任务。
> 本手册面向使用者；机制细节与安全边界的设计说明见 [远程访问指南](../remote-access.md)，往 `/mobile` 添加自定义页面见 [自带 /mobile 页面](../mobile-custom-page.md)。

## 它是怎么连的

桌面端运行时会同时托管两样东西（同一端口、同一进程）：

- **`/mobile` 页面** —— 手机端界面。静态资产，打开**无需令牌**（这样手机浏览器才能先拿到页面本身）；
- **运行时 API** —— 会话 / 审批 / 任务接口。**令牌门控**，无令牌一律拒绝。

手机浏览器打开 `/mobile` 后，页面与你桌面端**同源直连**（无 CORS、无云端中继、无账号体系）——访问令牌是唯一凭证，数据始终在你的局域网（或你自己的加密隧道）内流动。

## 前提

- 手机/平板与电脑在**同一局域网**（同一 Wi-Fi）；不在同一网络见「外网使用」一节；
- 桌面端安装版**自带手机页面**（随安装包分发，开箱即用）；老版本建议先升级。

## 第一步：桌面端开启局域网监听（LAN Direct）

桌面端默认只监听本机回环（`127.0.0.1`），出于安全考虑，桌面壳启动 sidecar 时会显式传入 `--host 127.0.0.1` 并覆盖 `RIVET_SERVE_HOST` 环境变量。要开放同一 Wi-Fi 手机直连：

**桌面端（推荐）** —— 打开 **设置 → 网络 → 远程访问（手机远程访问）**，开启 **「同一 Wi-Fi 直连」（开启局域网直连）** 开关：

1. 桌面端会自动以 `--host 0.0.0.0` 重启 sidecar，并注入 `RIVET_SERVE_LAN_DIRECT=1`（放行局域网明文 HTTP 监听，同时将 Host 白名单收紧至本机私网 IP）；
2. **首次开启会弹 Windows / macOS 防火墙询问，请选择「允许访问」（专用网络）**。若误点了拒绝：Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙 → 找到 `tianshu-desktop.exe`（及 `tianshu-runtime.exe`）勾选专用网络；
3. 开启后，设置页顶部徽章立即显示**「局域网可访问」**，并展示局域网访问地址与连接二维码。

**独立 CLI（无桌面端时）** —— 在终端显式 opt-in 启动 sidecar：

```bash
RIVET_SERVE_LAN_DIRECT=1 tianshu serve --host 0.0.0.0 --port 3100
```

## 第二步：手机连接

在桌面端 **设置 → 网络 → 远程访问** 区块：

1. 点令牌旁的「**显示**」（或开启「同一 Wi-Fi 直连」后直接查看二维码）。**令牌处于遮显状态时二维码不会绘制**，避免随手截图泄露令牌；
2. 二维码出现后，用手机相机（或系统浏览器扫码）扫码 → 自动打开连接页（`http://<lanIP>:<port>/mobile/#token=<access-token>`）并**自动连接**。令牌随即从手机地址栏被清掉，只保存在手机本地；
3. 手动方式：手机浏览器访问 `http://<地址>:<端口>/mobile/`，在配置页粘贴**访问令牌**即可（服务器地址自动填为页面来源地址）；
4. 电脑有多块网卡（有线 / Wi-Fi / Tailscale）时，区块里**每行地址都可点击**——点哪行，二维码就用哪个地址（该行高亮）。手机连哪个网段就选哪行。

> 端口以设置页「访问地址」显示为准——桌面端使用动态端口，每次启动可能不同；二维码与地址列表始终反映当前实际端口。

## 手机端能做什么

- **会话列表** —— 状态实时推送（连接异常时自动轮询兜底）；有**待审批 / 失败 / 中断**的会话带醒目色条并置顶；支持按正文关键词搜索；
- **会话详情** —— 只读时间线（实时流式）+ **审批处理**（授权 批准/驳回、执行计划 批准/驳回、提问的文本回复）+ **中止运行**按钮；
- **发起新任务** —— 从手机直接新建会话：选项目、输入任务；
- **会话产物** —— 查看该会话的产出。

已知边界（有意设计）：**已有会话不支持发消息/steer 干预**（避免手机上误改长任务的走向）；历史消息不支持「加载更早」冷分页；不支持 PWA 离线安装。刷新页面会回到列表页——扫码直达每次都是干净入口。

## 外网使用（不在同一网络）

**推荐 Tailscale（Tailscale Serve HTTPS 隧道或同网段组网）**：

1. 电脑和手机都安装 Tailscale、登录**同一账号**；
2. **方式一（HTTPS 隧道，推荐）**：桌面端保持回环即可，按「设置 → 网络 → 远程访问」给出的 `tailscale serve` 命令将本地端口映射为带可信证书的 `https://<机器名>.<tailnet>.ts.net` 地址，回填保存后扫码连接；
3. **方式二（Tailscale 虚拟网卡直连）**：开启桌面端「同一 Wi-Fi 直连」开关，在地址列表里点选 Tailscale 的 `100.x` 地址行作为二维码目标，手机扫码连接——全程走 Tailscale 加密隧道。

**不要把端口直接映射到公网。** 天枢没有账号体系、没有云中继，公网暴露后唯一的防线就是那串令牌。SSH 端口转发（`ssh -L <本地端口>:127.0.0.1:<serve端口> 用户@主机`）更适合从电脑访问，手机场景优先 Tailscale。

## 安全须知

- **令牌 = 完整控制权**，等同密码：不要截图、不要转发、不要写进公开配置。局域网模式下主机名校验会放宽，**Bearer 令牌是唯一凭证**；
- 局域网内是**明文 HTTP**：家庭/办公等可信网络使用；**公共 Wi-Fi 下慎用**（同网段可能被嗅探）。Tailscale 场景全程加密；
- **令牌与桌面端进程同生命周期**：重启天枢后旧令牌立即失效，手机端会连不上（401）——重新扫码即可；
- 可选收紧：`RIVET_SERVE_HOSTS_ALLOW=192.168.1.5,my-pc.local`（逗号分隔、不带端口）可启用主机白名单，非白名单 Host 直接拒绝。

## 常见问题

| 现象 | 处理 |
|---|---|
| 扫码打开是 **404** | 该服务实例未提供 `/mobile`。桌面安装版随包提供（正常不会出现）；自己用 CLI `tianshu serve` 时需要 `RIVET_MOBILE_DIR`（或 `--mobile-dir`）指向含 `mobile.html` 的目录 |
| 打开后**连不上 / 401** | 桌面端重启过，令牌已轮换——重新扫码；或在手机端「更换连接」粘贴新令牌 |
| 手机打不开地址 | 依次检查：设置页徽章是否「局域网可访问」→ 手机与电脑是否同一网段 → 防火墙是否放行 → 地址行的 IP 是否选对（多网卡时） |
| 想彻底关闭远程访问 | 在桌面端「设置 → 网络 → 远程访问」关闭「同一 Wi-Fi 直连」开关（并清除已保存的隧道地址），sidecar 立即切回仅本机 `127.0.0.1` 回环监听 |

快速自检（在电脑上执行，不需要令牌）：

```bash
curl -o /dev/null -w '%{http_code}\n' http://127.0.0.1:<端口>/mobile/   # 期望 200
```
