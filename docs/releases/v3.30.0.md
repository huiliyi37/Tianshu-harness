# v3.30.0 发布记录

本版主线是「把自动更新链端到端真打一遍」：三个已发布版本（3.29.0–3.29.2）的桌面端更新实际上全灭于存量会话的落盘核对死等，本版根修并配齐逃生门与灰度策略门。

## 1. 自动更新链（端到端实战修复）

- **存量会话死等根修**（`9ce498631`）：flushThrough 只追本进程写链的内存水位，rehydrate 的存量会话恒 0 < seq → 死等吃满 30s 预算，「未能确认保存完成」恒报。改读盘上高水位——175 个存量会话实测 30s 必死 → 1.5s。**3.29.0–3.29.2 的桌面用户需手动覆盖安装一次本版**才能恢复自动更新
- **保存失败的引导与逃生门**（`32a224a32`）：busy_timeout 独立成类（僵尸任务不再误报保存失败）+「停止任务并更新」出口；真·保存失败给「仍然更新（未保存的更改可能丢失）」知情逃生门（allowUnsaved 全链透传）
- **更新重启后窗口置前**（`5d9cc6304`）：relaunch 拉起的新进程在 macOS 是后台应用，窗口不置前——更新重启标记 + 主窗 page_load 置前（10 分钟新鲜度门）
- **单架构打包也重建 CLI 运行时**（`a7ddfb202`）：单架构模式原先跳过根运行时重建，「新 Rust 壳 + 旧 JS 运行时」拼装会让新特性整包缺失（本次 LAN Direct 崩溃循环的根因）
- **受控灰度更新上线**（`b088b5c14` + `95bacb79e`）：update-control 策略门（stable/candidate/revoked + 按平台百分比灰度 + 预览通道）+ 发布侧 publish-update-control 工具链（本版已用它完成初始化发布，stable=3.29.2 → 本版发布后 promote 到 3.30.0）

## 2. 相位机与感知

- **相位机三修**（`1004aff36`）：isWriting 改走写工具全族（hash_edit/ast_edit/apply_patch 不再误判「没在写」）；后台 job 活动计入推进证据；plan 类相位进入门禁——执行/验证/交付中的会话不再无信号退回规划（「还没交付就又进 plan」的误报话术消失）
- **输入请求句不再误触发 action-intent reminder**（`4a40b3d33`）：「给我目标或文件，我先读现状再动手」这类等用户输入的复合句不再被当成悬空承诺

## 3. 交付门与验证归因

- **无 coverage 的失败不再被当成「从未验证」**（`405bfc4c1`）：隔离快照失败拿不到覆盖元数据的记录按命令文本兜底归因进 failed 档，共享工作区下不再是永久覆盖缺口
- **覆盖判定改逐文件**（`7011ac00a`）：整批失败不再作废批内其他文件的通过证据
- **Windows 命令路径归一化**（`ca58e6519`）：反斜杠 / `./` 前缀命令形态同样能归因

## 4. 安全与社区收编

- **file-context 路由工作区守卫**（收编 PR #407，`0fbf9e2b5`）：GET /workspace/file-context 的 cwd 必须命中已注册工作区——Bearer 持有者不再能枚举任意目录结构（CWE-862，与 #221 同族）
- **显式插队引导**（收编 PR #406 部分，`723f3cc6d`）：Alt+Enter / `/steer` 以 now 优先级进 steer 队列，下一个工具边界立即注入；普通 Enter 的 later 语义不变

## 升级注意

- **桌面端自动更新链在本版修复**——3.29.0–3.29.2 用户需**手动下载覆盖安装一次**（官网 tianshuharness.com/download 或 GitHub Release），之后的版本恢复自动更新。数据在本地目录不受影响
- 更新失败时的指引全面重写：busy 超时给「停止任务并更新」，保存失败给「仍然更新/手动下载」三条出路
