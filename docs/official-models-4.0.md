# 4.0 官方模型接入

本次适配以 Tianshu4.0 的账号归属、官方模型和原生直连协议为标准，同时保留公开 CLI 已有的工具、审查、只读快照、恢复和运行时观测能力。桌面界面、Pro 实现及部署凭据不属于公开投影。

## 使用

1. 在 TUI 使用 `/login account`，在官网完成设备授权。
2. 在模型列表选择官方模型。模型目录、可用绑定、上下文和输出上限来自官网，不需要手工填供应商 Key。
3. 充值、订单和退款在官网办理；客户端显示后台返回的实际额度状态。

目录首次成功获取后复用；失败、账号变更及显式刷新走各自的恢复路径。官网模型更新由目录和版本约束控制，不把旧账号的模型授权借给新账号，也不把临时网络失败当作退出登录。

## 发送链路

- 启动和选择模型时完成目录、账号、模型用途与绑定核验。
- 支持直连的账号通过正常鉴权交换获得有限、短期授权；供应商模型请求由原生进程直接发送。
- 有效的热授权不在每次发送前查询报价、目录或余额。额度刷新在发送链路之外进行。
- 不支持或未获直连授权的路由仍按服务端发布的协议处理，不静默改成其他账号、模型或服务商。
- 输出必须满足相应协议的完成条件。流中断、错误信封和取消不得伪装成完整回复，也不得自动重放结果未知的调用。

官网发布的上下文和输出上限是配置能力，不代表任意上游都实际完成过该极限长度的压力测试。

## 凭据与额度

供应商管理令牌只在服务端使用。调用凭据不写进应用源码、安装包、渲染器响应或明文配置；原生直连租约在进程内存中使用，账号会话使用平台加密存储。内存中的凭据不能宣称对设备所有者不可提取。

Key 归属于账号。退出一台设备只清除并撤销该设备的会话，不撤销其他设备或整个账号的供应商 Key。迟到的授权响应必须受原账号、会话和本地世代约束，不能把退出前的凭据重新装回。

充值由服务端根据可信订单状态去重履约，按当前产品或兑换规则增加专属 API 可用额度。浏览器回跳不等于付款成功，客户端不能自行加余额。供应商扣费、有限额度及余额耗尽限制仍由后台负责。

## 兼容与验证

保留 BYOK、OAuth、四种模型协议、模型切换失败后的原会话、工具挂载提示、只读审查快照和运行时观测。官方错误经过工具终态审计后仍保持原始类型，不能变成普通工具文本后触发下一轮模型发送。

项目概况扫描的首轮等待最多 100ms，后台扫描继续完成；取消时立即交还运行生命周期。Git 状态未变化时，变更率和交付指纹避免重复启动 Git 子进程；HEAD 或 index 改变时必须重新核验。

启动图基线为 614 个模块。本次增加 33 个协议、账号、模型、恢复、项目概况和共享呈现模块（含原生设备元数据），实测 647；无模块退出。八个禁止进入启动图的 agent/TUI 重模块仍不可达，bare 包集合不变，解析失败集合为空。启动图上限钉在实测 647，不提供额外余量。原有源码行数预算不提高，新增职责沿模块边界拆分。

针对性检查：

```sh
npm run typecheck
npm run build
npm run budgets:check
npm test official- account- managed- model-runtime model-binding
npm test execution-continuity openai-client anthropic-client gemini-client responses-client retry-engine

```

模拟协议测试、真实原生调用、真实浏览器渲染、全量测试以及全用户充值验收是不同证据，不能相互替代。发布说明和 PR 应分别列明通过、未通过、跳过和未执行的项目。
